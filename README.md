# lc-coach · 刷题教练

一个本地跑的刷题教练：每天告诉你做哪几道、每题给三个解法（暴力 → 较好 → 最优）配中文伪代码、错题本、代码模板库。复用你自己的力扣账号同步已解决题目。

- 计划：16 周 / 112 天 / 120 道题，起点 2026-11-02
- 内容：120 道题 × 3 解法，**360 份 Java 代码全部通过 javac 编译**，每份都有中文 `idea`（讲为什么）和可逐行翻译的中文伪代码
- 技术栈：Spring Boot 2.7.3 + spring-boot-starter-jdbc + H2 1.4.200，前端原生 HTML/CSS/JS 无框架

## 怎么跑

双击 `启动-免编译.cmd`（jar 已经打好），浏览器会自己打开 http://127.0.0.1:8099 。

改了 Java 代码才需要双击 `启动.cmd`（会先 mvn package）。

命令行：

```bash
java -jar target/lc-coach-1.0.0.jar
```

## AI 资讯（AIHOT）

数据来自 [AIHOT](https://aihot.news)，匿名只读接口，不需要 API Key。

**为什么只做了「看」，没做「自动写进计划」**：资讯是每天变的外部输入，自动塞进刷题目录会让计划漂移，而且没法保证相关性。这块保持只读，要看就点进去看。

**缓存策略（这块是接入的重点，不是套话）**：AIHOT 的响应头写着 `Cache-Control: public, must-revalidate, max-age=60, s-maxage=60`，单 IP 大约 60 次/分钟会 429。所以 `AihotService` 每条请求过三道闸：

1. **60 秒内直接返回本地缓存**，一个字节都不发出去
2. 过了新鲜期 → 带 `If-None-Match` 去问，没变就是 **304 空 body**，只刷新时间戳
3. 被 429 打了 → 按 `Retry-After` 记住冷却截止时间，冷却期内直接用缓存

另外每个上游路径一把锁（single-flight），防止两个请求同时发现缓存过期、同时打上游把自己限流。上游连不上时降级返回旧数据，页面上会明确写出「先给你看缓存的数据」，不会假装是新的。

**为什么用 `/api/v1` 而不是 `/api/v1/agent`**：`/agent/*` 返回的是给大模型读的 Markdown，官方明确说「要写程序做定时同步、推送或维护本地副本，不要用这套」。

**许可**：个人非商业使用免费。lc-coach 是自用项目，属于这个范围。任何对外提供的商业产品、收费服务、公开镜像、批量再分发都需另行取得 AIHOT 书面授权——标注来源不等于已授权。条款见 https://aihot.news/terms

### 今日页的「今日模板」卡

今日任务和连续打卡之间会插一张模板库里的代码段，带一句话说明。**用年月日做种子取模**：

```js
const seed = d.getFullYear() * 10000 + (d.getMonth() + 1) * 100 + d.getDate();
const pick = list[seed % list.length];
```

好处是同一天刷新几百次都是同一个模板（不会每刷新一次就换，那样等于没记住），跨天才换下一个。16 个模板轮一圈大约半个月，比真随机的重复率低。

配的说明不是凑数——每个模板都得能在面试前扫一眼就想起来「这玩意儿什么时候用」。比如「网格 DFS 递归深度可能到 m×n 会爆栈，数据大时改用 BFS 或并查集」。文案存在 `snippet.note` 字段里，改文案不用碰代码，进模板库页改就行。

### 日历卡上的「前一天 / 后一天」

`.day-counter` 右侧两个箭头，翻看计划里任意一天的安排。路由是 `#/today`（今天）和 `#/today/N`（第 N 天）。

**三个决定值得记下来：**

1. **翻页只看，不改。** 翻到第 3 天不会把「今天」改成第 3 天。`State.today` 存真实今天（侧栏统计、计划页、打卡都读它），`State.todayView` 存当前正在看的那天。不分开的话，翻一眼历史再点个勾，连续天数和进度条就跟着跳了。
2. **边界由后端给。** `hasPrev` / `hasNext` 从 `/api/today?day=N` 返回，前端不写死 112。天数只有一个来源，改计划长度不用改前端。`day=0`、`day=113`、负数都会被夹到 `[1, 112]`，不返回空页。
3. **打卡和日期无关 —— 任何一天的题都能勾。** 曾经这里写着「历史页的打卡按钮是停用的，因为那个勾写进的是真实今天的进度」，这是个错误的理解：`progress` 表的主键是 `slug`，`done_date` 只记第一次完成的日期，压根没有「哪天做了多少」这种按日切分的账。给第 3 天的题打卡，就是把那道题标记成做过，天经地义。按日期拦着的结果是昨天/明天的 ✓ 点了没反应，而按钮看上去是能点的 —— 纯属骗人。
   打卡后只刷新**当前正在看的那一天**（`refreshToday(t.isToday === false ? t.dayNo : null)`），不能无条件调 `refreshToday(null)`，否则在历史页点勾会把 `State.today` 覆盖成真实今天，侧栏统计跟着跳。

顺带加了键盘 `←` `→` 翻页（输入框里按不触发），换页面时 `document.onkeydown` 会被清掉，否则在题库里按左键会莫名其妙跳去前一天。

```java
// PlanService.dayAt(Integer wantDay) —— wantDay 为 null 表示今天
boolean lookingAtToday = (realDay == 0 ? 1 : realDay) == dayNo;
out.put("isToday", lookingAtToday);
out.put("date", startDate.plusDays(dayNo - 1L).toString());
out.put("hasPrev", dayNo > 1);
out.put("hasNext", dayNo < totalDays());
```

**一个测试教训**：`test-lock-click.js` 原来用 `await sleep(900)` 等页面渲染，连跑三次有一次失败。冷启动、GC 抖动、H2 查询变慢都会超过 900ms，于是拿上一次渲染的旧 `innerHTML` 做断言。改成 `waitFor(cond, 8000)` 轮询真实条件后连跑五次全过。**偶发失败的测试比没有测试更坏 —— 真回归失败会被当成噪声忽略掉。**

## 每日提醒怎么工作

`ReminderService` 每 60 秒检查一次：当前时间过了设定时刻、且今天还没发过，就生成一条站内信，内容是今天该做的几道题（含中文标题）。

- 默认 **每天 08:00**，在「提醒」页可以改时间、开关。
- **不需要任何外部推送服务**（不要 token、不要公网），打开页面就能看到红点。这是刻意的取舍：离线可用，不给部署添麻烦。
- 用 `fixedDelay` 每 60 秒扫一次而不是精确 cron，是因为应用可能随时重启——精确 cron 会漏掉当天已经过去的时刻，每分钟「补课」式检查能保证重启后补发。
- 幂等：`(day_date, kind)` 决定同一天只发一次，重启不会刷屏。
  **这里踩过一个坑：早期代码写死查重 `kind="daily"`，但预览期实际写入的是 `kind="preview"`，于是每分钟都判定「daily 还没发过」→ 又插一条 preview，一天堆了一百多条「距离开跑还有 1 天」。** 现在先算出今天该发哪一类、再用同一类去查重：
  ```java
  String kind = Boolean.TRUE.equals(plan.today().get("preview")) ? "preview" : "daily";
  if (alreadySent(today, kind)) return;
  ```
- 想立刻看到效果，点「立即试一下」。

站内信的局限要说清楚：**它不会在你没打开浏览器时弹窗**。浏览器原生通知（Notification API）需要 HTTPS 或 localhost + 用户授权，还要 Service Worker 才能在关页面后推送，复杂度不成比例。要手机推送得自己接钉钉/飞书/Server酱的 webhook——`ReminderService.pushDaily()` 里加一行 HTTP 调用即可，接口已经隔出来了。


## 绑定力扣账号（可选）

打开 leetcode.cn 登录后，F12 → Application → Cookies → 复制整条 Cookie 字符串，粘到「账号」页。绑定后点「同步」拉取已解决题目，今日页会显示哪些题你已经过了。

不绑定也能用全部功能，只是不会同步已解决状态。

同步会做两件事：
1. 把力扣上 `status=AC` 的题写进 `solved_snapshot`（账号页列表）；
2. **把落在 120 题计划里的那些题回写进 `progress` 标成 done** —— 这样计划里不会让你重做已经 AC 过的题。

第 2 步只补不删：你在本地手动标过的 done 和写的 `my_note` 笔记都不会被同步覆盖。

> Cookie 里有 `LEETCODE_SESSION`，等同于你的登录凭证。它只存在本地 H2 数据库 `data/lccoach.mv.db` 里，不会发到任何第三方。不想用了在账号页点「解绑」即可清除。

## 题目页长什么样

每道题三个 tab：

1. **暴力** —— 最直白的解法，先把语义钉死（返回什么哨兵值、改不改入参）
2. **较好** —— 换数据结构或思路，说明相对暴力改了什么
3. **最优** —— 目标复杂度解法，点明最容易写错的那一行

每个 tab 三块内容：`idea`（为什么这么想，含反例和坑）、`伪代码`（中文编号，能直接逐行翻成 Java）、`代码`（可复制）。底部有三问，逼你自己先想 30 秒再看答案。

### 「我的代码」和评分

每个解法 tab 下面还有一块「我的代码」，就是你说的那个「像力扣一样能写代码的地方」。

做法是**把在力扣写的代码整段粘进来**，点「评分」，后端拿 JDK 自带的 `JavaCompiler` **真的编译一遍**，再拿官方示例用例**真的跑一遍**看答案对不对，最后对代码做静态结构分析。七个维度各给 10 分：

| 维度 | 权重 | 怎么算的 | 可验证性 |
| --- | --- | --- | --- |
| 编译通过 | 0.12 | `javac` 真跑，报错原文返回（「第 6 行：需要';'」这种） | **实测** |
| 正确性（真跑） | 0.30 | 编译出的 class 当场加载，逐个官方示例用例跑，比对返回值 | **实测** |
| 思路匹配 | 0.14 | 识别代码里用到的手法（哈希/双指针/二分/DP/BFS…），和最优解比对 | 推断 |
| 时间复杂度 | 0.16 | 数循环嵌套层数 + 是否递归/二分/排序，映射成 O(1)~O(n³) 档位 | 推断 |
| 空间复杂度 | 0.10 | 看有没有开哈希表/辅助数组/递归栈 | 推断 |
| 边界处理 | 0.10 | 风险扫描：直接取下标却没判长度、除法没判零、强制类型转换 | 推断 |
| 代码规范 | 0.08 | 方法体行数、嵌套深度、单字母变量、魔法数字、有没有注释 | 推断 |

**权重是按可信度分配的**：两项实测加起来 0.42，比其余五项加起来还接近一半。正确性一项（0.30）比任何两项推断都重 —— 答案错了，思路再漂亮也是白搭。

**前端会明确标出哪一项是「实测」哪一项是「推断」**。判题判不了的时候（见下一节），「正确性」整项从加权里**剔除并重新归一**，而不是按 0 分算 —— 判不了 ≠ 你没做对。

两条一票否决：

- 编译不过 → 总分封顶 **3.9**，说别的都没意义
- 编译过但方法名不是力扣要调用的（比如把 `twoSum` 写成 `solve`）→ 封顶 **5.5**，因为判题器是按方法名反射调用的，名字不对等于交不上

再加两条与正确性挂钩的：

- 有用例没过 → 封顶 **7.9**（有 3 个用例过了 2 个，也不能算「差不多对」）
- 通过率不到一半 → 再压到 **6.9**

通过率到分数的映射刻意做成**非线性**的 `1 + 9 × rate²`：过一半（rate=0.5）只有 5.0 分。因为「一半用例错了」的代码不是「差不多对」，是「方向可能就偏了」。

## 评分器为什么要真跑判题

最早这一项是**完全不判**的，页面底部写着一句「没有测试用例，所以这里不判答案对不对」。这在当时是诚实的 —— 项目里确实一条用例都没有，只有展示用的题面 HTML。但后果是：你可以写一段根本不是解法的代码，只要编译过、手法像样，就能拿到 9 分以上。

现在改成真跑了。整件事有三道坎：

### 坎一：用例从哪来

力扣的 GraphQL 接口 `question(titleSlug:){exampleTestcases metaData}` 能拿到**官方示例输入**（`[2,7,11,15]\n9\n[3,2,4]\n6`）和**方法签名**（`{"name":"twoSum","params":[{"name":"nums","type":"integer[]"},{"name":"target","type":"integer"}],"return":{"type":"integer[]"}}`）。

但**期望输出它不给**。这里我犯过一个错，必须写下来：

> 第一版是「拿我们自己写的参考最优解跑一遍，跑出来的就是标准答案」。听起来合理，实际是**循环论证** —— 参考解判自己永远全过，这个比较永远量不出任何东西。

它一直没露馅，直到用户拿一段在力扣击败 97.82% 的正确代码提交上来，被判 0/3。查下去发现两件事：

1. `longest-consecutive-sequence` 的 optimal 参考解**自己就是错的**（`map.put(x + 1 + right, len)` 多加了 1，右端点错位一格）
2. 更根本的是 —— **力扣 `exampleTestcases` 返回的输入和题面示例对不上**。`count-primes` 题面示例是 `n = 10 / 0 / 1`，接口返回 `"0\n1\n2"`。这类错位查出来 10 题

所以现在的做法是：**期望值和输入都从题面 HTML 解析**（题面本来就写着「示例 1：输入：… 输出：4」），`exampleTestcases` 只在题面解析不出来时兜底。

解析器在 `content-src/_probe-coverage.js`：先把 HTML 转纯文本（`<br>` 换行、剥标签、还原 `&lt;` `&nbsp;` 这些实体），再用 `输入[：:](...?)输出[：:](...?)` 匹配，输出边界靠「示例 N / 提示 / 解释 / 进阶」这些哨兵词判定 —— 早期版本用换行当边界太松，会把「示例 2：输入：…」整段吸进输出里。

**117/120 题解析成功**，重建成 `content/tests/<slug>.json`（115 题）。参考解现在只做**交叉校验**：它要是在某个用例上和题面期望不一致，会记一条 `refNote`「错的是参考解，你的提交按题面判」，而不是拿它当标准。

拉下来的用例存在 `content/tests/<slug>.json`，随代码分发。

### 坎二：用户代码在哪跑

正常做法是把代码编译成 class 再起一个 `java` 进程跑，沙箱隔离干净。**但这台机器禁止任何子进程**：

```
ProcessBuilder.start()        → CreatePipe error=5, 拒绝访问
改成全用文件重定向（不建管道）  → 进程能起，但 EXIT -1073741502（STATUS_DLL_INIT_FAILED）
连 cmd /c echo hello 都这样   → exit=-1073741502，输出为空
```

所以退到**同进程执行**：`ToolProvider.getSystemJavaCompiler()` 编译出来之后，用 `URLClassLoader` 把 class 加载进当前 JVM，反射调用方法。代价是隔离性差 —— 用户代码和服务在同一个进程里。为此加了两道保护：

- **每个用例 3 秒超时**，`ExecutorService` + `Future.get(timeout)`，死循环掐掉而不是挂住整个服务
- **截获 `System.out`**，避免用户代码狂打印把日志刷爆

`setAccessible(true)` 是必须的：`Solution` 在默认包、方法不是 public 可见，不加就 `IllegalAccessException`。

### 坎三：判不了怎么办

120 题里 **108 题能真判**，12 题判不了。原因全是**类型系统表达不了**，不是逻辑问题：

| 题目 | 为什么判不了 |
| --- | --- |
| `lru-cache` / `min-stack` / `implement-queue-using-stacks` / `implement-trie-prefix-tree` / `find-median-from-data-stream` | 设计类题，是一整个类，没有单一 `Solution` 函数 |
| `linked-list-cycle` / `linked-list-cycle-ii` | 比的是「返回的节点是不是同一个引用」，不是值；而且用例只给节点数组，构不出环 |
| `intersection-of-two-linked-lists` | 要求返回两条链表的交点节点，用例造不出共享节点 |
| `lowest-common-ancestor-of-a-binary-tree` | 传入的是树里的节点对象，不是可序列化的值 |
| `clone-graph` | 需要题目自带的 `Node` 类定义，判题器里没有 |
| `convert-sorted-array-to-binary-search-tree` | 正确答案不唯一，形状不一样也算对 |
| `course-schedule-ii` | 拓扑排序的正确顺序不止一种 |

最后两行和上面的原因不同：不是**表达不了**，是**答案不唯一**。这类题硬判只会把对的判成错的 —— 那比不判更害人。所以有一张 `UNJUDGEABLE` 表，命中就不判，并明确告诉你为什么。

这 12 题的处理是**把「正确性」维度整个剔除**，总分按剩下六项重新归一，前端明确显示「这题不支持真跑判题，已从加权里剔除，不是按 0 分算」。

**不给 0 分是有意的**：判不了是我这边能力不足，不该记在你头上。

### 判题器踩过的坑（每一条都曾经把对的判成错的）

修这些的时候，27 题报「参考解写错」，逐题查完发现 **25 题是判题器的 bug，只有 2 题是参考解真错**：

| 坑 | 症状 | 修法 |
| --- | --- | --- |
| `ArrayDeque` 不收 null | 树题的 `serializeTree` 静默抛 NPE 被 catch 成 `[]`，**每道树题都判答案错** | 换 `java.util.LinkedList`；catch 里不再返回 `"[]"` 而是报「判题器出错，这一条不算你的错」 |
| 浮点按字符串比 | `1024.00000` 和 `1024.0` 判成不同 | `same()` 里加 `1e-5` 相对误差比较 |
| 空值两种写法 | 题面写 `[]`、代码返回 `null`，判成不同 | 都归一成「空」 |
| void 题把入参拼一起 | `rotate-array` 期望 `[5,6,7,1,2,3,4]`，实际 `[[5,6,7,1,2,3,4],3]` | 逐个入参试，挑跟期望一致的那个 |
| 多解顺序 | `group-anagrams` 组内组间顺序都不唯一 | `deepSortedForm()` 两层排序后比 |
| `orderFree` 赋值太晚 | 比对时恒为 `false`，等于没开 | 挪到参考解执行**之前** |
| 题面用单引号表示字符 | `['1','1']` 不是合法 JSON | `JSON.parse` → 改内容 → `JSON.stringify` 写回（直接文本替换会把文件弄坏） |
| `spiral-matrix` 收边界 | 单行时多收一行，3×4 矩阵第 2 圈多一个 `6` | 下边只在 `top < bottom` 时收、左边只在 `left < right` 时收 |

还有两个是**参考解自己写错了**，属于内容 bug 不是判题器 bug：

- `longest-consecutive-sequence`：`map.put(x + 1 + right, len)` → `map.put(x + right, len)`
- `binary-tree-maximum-path-sum`：按「根右左」压栈后注释写「倒着遍历」，代码却是正着 `for` —— 孩子还没算就算父亲，答案退回单节点值。改成倒序下标循环

| 提交 | 改前 | 改后 |
| --- | --- | --- |
| 两数之和，正确的哈希解法 | 10.0 | **10.0**（3/3 全过） |
| 两数之和，写死 `return new int[]{0,1}` | **9.5**（虚高） | **6.9**（2/3，正确性 5.0 分） |
| LRU 缓存，参考解 | — | 10.0（判不了，正确性维度剔除） |

第二行是这次改造最直接的证据：一段**根本没解题**的代码，从 9.5 掉到 6.9，还附上了具体错在哪 —— 用例 2 输入 `[3,2,4], 6`，期望 `[1,2]`，你给了 `[0,1]`。

还有一条来自用户的真实反馈，是这轮改造的起点：他在力扣击败 97.82% 的 `longest-consecutive-sequence` 写法，在这里被判 0/3。修完之后同一段代码 **3/3 全过，总分 9.7**。

### 为什么 run-all.sh 要数两种勾

`test-judge.js` 和 `test-judge-ui.js` 用的是 `✔/✘`，其余脚本用 `✅/❌`。跑批脚本一开始只数 `✅`，这两个脚本就显示「0 条断言」还打绿勾 —— **看起来通过了，实际一条都没统计到**。这比测试失败更糟：失败至少会红。

现在两种都数，并且断言总数为 0 时直接判失败，不让它混在全绿里。

### 内置三个解法也用同一套标准打分

评分器对参考解法走的是**同一个 `grade()` 方法**，基准统一取该题的**最优解**。所以「你的分数 vs 最优解的分数」是可比的。

参考分数显示在**两个地方**（顶部那条汇总分数条已按用户要求移除，避免同一份分数画两遍、让人以为有两套标准）：

- 每张解法卡内部（tab 下方第一块），六个维度逐项列出，一眼看出这个解法强在复杂度还是弱在边界
- 三个 tab 上各有一个小分数角标，不点开也能看出谁高谁低

#### 两条不变量：零点要在 10，顺序不能反

用户提过一次很尖锐的质疑：「我写的移动零只打败 10% 的人，凭什么比你标着最优解的那份分还高？」这一问逼出两条不变量：

1. **零点**：参考最优解必须 10 分。不然「你的分数 vs 最优解的分数」这个对比根本不成立。
2. **顺序**：brute ≤ better ≤ optimal。分数是量解法质量的尺子，尺子不能把「更好的解法」量成更低分。

用户后来还纠正过一次我的方向：「也不是说最优解一定要十分，我希望就是你的最优解起码在力扣中不能太低，也是力扣中的最优解」。这条纠正是对的 —— **要保证的是解法本身够硬，不是分数凑整**。所以除了钉分数，还钉了一条语义断言：题解自己声明的复杂度也不能倒挂（`test-grade.js` 第 10 节）。

- **统一基准**。最初让每个参考解法各拿自己当基准，复杂度永远判成「同级」，实测出现过 **brute 9.2 反超 optimal 9.1**。改成统一以 optimal 为基准后差距才显出来。
- **扣分规则两边都要跑**。这是慢写法反超用户代码的真正原因：早期只有用户代码过扫描，参考解从不跑一遍。「直接下标访问没先判长度」几乎每道数组题的参考解都会触发，恒被扣 3 分；「一行注释都没有」把参考解压到 9 分，而用户写 11 行短解法反而白拿 10 分。现在两边跑同一套 `scanEdge` / `scanStyle`，**参考解已经踩到的风险项不计入用户扣分**（只会写在「参考解同样有：…」里）。
- **`space` 只扣参考解没用的手法**。参考解自己开了哈希表，就不该因为用户也开哈希表而扣分。
- **`approach` 识别不出手法时不扣分**。原逻辑是「参考解没体现出明确套路 → 给 7 分」，那是检测器盲区，凭什么算用户过错。现在给 10 分并注明「这一项无法判定」。
- **单项塌陷封顶**。加权平均有个结构性缺陷：一个维度砸到 1 分、其余五项满分，总分仍有 8.2。所以 `complexity` 或 `space` 低于 4 分时总分封顶 **7.9**——用封顶而不是加大权重，是为了不动六项相对比例，只堵「一项烂、五项救」。
- **参考解之间的相对校正**。120 题里有 11 题，brute 和 optimal 的**代码结构在估算器眼里完全一样**（`sqrtx` 的 O(√x) 和 O(log log x) 都是单层 while；`hamming-distance` 的 O(32) 和 O(k) 都是位运算）。差异在常数因子和对数的对数这一级，正则量不出来。这类题用题解里**人工声明的复杂度**做相对校正（`fineRank` / `applyDeclaredRank`，每档 1.2 分），**且只用于参考解之间排高低，绝不参与用户评分**——用户代码没有声明可比，硬拿声明校正用户等于拿答案扣分。

- **单调上限**（压轴的一条）。上面几条修完，单调从 89/120 到 110/120 就卡住了。剩下 10 题逐维度归因，全是三样**静态分析看不穿**的东西：

  | 看不穿的东西 | 例子 |
  | --- | --- |
  | 常数层循环被数成嵌套 | `single-number-ii` 的 `for (b = 0; b < 32; b++)` 判成 O(n²) |
  | 摊还分析 | `count-primes` 的 O(n log log n) 看不出来 |
  | 时间换空间被当退步 | `clone-graph` 的 better 用递归换 O(1) 时间、代价栈 O(n)，被 space 项扣分 |

  但复杂度声明顺序我已经独立核过：**119/120 题的时间声明是对的**。也就是说「brute 比 better 慢」是**被验证为真的偏序** —— 度量把已核实为真的顺序排反了，要修的是度量，不是宣布真顺序是错的。所以在 `gradeReference` 里按声明复杂度定序，声明更慢的那一档分数不得超过更快的那一档（`monotoneNote` 标记）。**只压不抬**，且只作用于参考解之间，用户评分完全不受影响。

  定序第一版写错过：只按 `fineRank` 升序加 `cap = min`，同档的题（`reverse-linked-list` 的 brute 和 better 都是 O(n)）排序不稳定，封顶随机生效。改成显式 `Comparator`：先按 `fineRank`，同档再按 tier 高低（optimal > better > brute）。

修完的实测数据：**120/120 参考最优解全部 10.0**，**三解法单调 120/120，0 题倒挂**。brute 分数分布 min=2 / 中位=6.9 / max=10。

> **内容层也修了两处 tier 标签**：
> - `network-delay-time`：Floyd-Warshall 那条文案自己写着「如果你不假思索地想到『先把所有点对的最短路都算出来』，那就是 Floyd-Warshall」，而 Bellman-Ford 那条写着「对稠密图 O(n·E) = O(n³) 和 Floyd 一样，但常数小得多」—— Floyd 才是笨办法。已把 Floyd 改成 brute、Bellman-Ford 改成 better。
> - `single-number`：`HashMap` 是 O(n)、`Arrays.sort` 是 O(n log n)，顺序标反了。
>
> 两处都只改 tier 与 `sortOrder`，代码和文案一个字没动 —— 它们本身写的是对的。

> 复杂度这一项踩过一次弯路：试过「基准取声明与实测中更优的那个」，结果基准变宽松后**参考解自己被判「比基准多 2 档」，58 题掉到 7.9**。结论是这一项的唯一正确不变量只有「两边同一把尺子」，题解声明只用于展示和参考解之间的相对校正。

### 锐评（`static/roast.js`）

评分卡最底下会来一段毒舌点评。**它不是随机抽一句狠话**，四条设计红线写死在代码注释里：

1. **每句话都能追到真实数据** —— 编译报错原文、某个维度的分数、evidence 里那一行。说不出原因的毒舌和说不出原因的夸奖一样没有价值。
2. **骂的是代码，不是你** —— 所以永远带「然后呢」这一段给下一步。光骂不给方向就是耍流氓。
3. **分数不同，骂法不同**：

| 情况 | 说的话 |
| --- | --- |
| 编译不过 | 优先于任何分数档。「javac 都没让你过」「后面五项评分是在给一具尸体量体温」，并引用真实报错行 |
| 方法名错 | 「代码能跑，但力扣调不到你」，点名期望签名 `twoSum(int[], int)`，说明这是白丢分 |
| < 5 分 | 「离能过还隔着一段距离」「努力程度值得肯定，方向值得怀疑」 |
| 5~7 分 | 「只是能跑」「面试官会往下问三轮」「抄了个形状」 |
| 7~8.5 分 | 「不错在面试里是最容易被刷掉的那一档」 |
| ≥ 8.5 分 | 不硬找茬。「这题你是真懂了」「该有的都有，不该有的都没有」，建议往前走 |

4. **同一份代码说同一句话** —— 用分数 hash 做种子，不会每次刷新都换一张嘴。

靶子永远是六个维度里**最弱的那一项**，并把它 evidence 的第一条原话引出来。满分时不硬挑刺，只说「没有短板，别磨了，往前走」。

先看到「这道题的满分长什么样」，再动手写。

### 错题本：评分之后可以「自动填写」（`static/mistake-fill.js`）

写完代码、点了评分，再点「记入错题本」，弹窗右侧会多一栏**自动填写**。

它做的事很具体：把**你这次的评分**和**这道题的最优解评分**逐维度对比，然后

- 「卡在哪」→ 挑**差距最大**的那一项，但写成**你自己回头看笔记的口吻**，不是诊断报告。例如：
  > 我想到的是先排序，没往哈希表上想，HashMap 的 put / getOrDefault 那几行我现在还写不出来。
  > 我写成的是 O(n^2)，最优解是 O(n)，差的就是那层循环套循环。
- 「一句话结论」→ 下次该先抓什么。例如：
  > 下次先想「哈希表」这条路 —— 它能把 O(n^2) 压到 O(n)。
- 「分类」→ 题目自带 tag 优先，没有才退回最优解的主手法

**分数差、维度名、「识别到的手法：排序」「最大循环嵌套 2 层」这类机器判据原文，一律不进正文**，只进右侧那块「依据」。正文是写给你自己看的，不是写给日志看的 —— 抄一遍机器输出对你下次做题没有任何帮助。

手法名会先翻成人话：`哈希` → 哈希表、`BFS` → 广搜、`辅助数组` → 另开数组存。没登记的手法原样输出，不会变成 `undefined`。

另外，点击后会在右侧追加一块「依据」，写明这两句话是怎么算出来的（卡点取的是哪一项、哪些手法是漏掉的），**不让你面对两段没有来源的文字**。

四条设计红线：

1. **不编**。没评分就不给按钮，只说明「先点一次评分，我才能算出你和最优解差在哪里。没评分就没有对比数据，硬编一段话只是骗你。」
2. **说人话**。第一人称，写「我怎么想的、我漏了什么」；「思路匹配分低」「识别到的手法：排序」这类机器输出不是人能用的信息。
3. **编译不过 / 方法名错的优先级高于一切维度差距**。语法都没过的时候去讨论时间复杂度是浪费时间。
4. **填完能改**。只填当前为空的框，不覆盖你已经手写的内容；填完光标自动停在「卡在哪」，按钮变「已填好，可以改」并禁用。

> 数据来源上踩过一个坑：最优解的手法集合 `refTechs` 原本**只出现在后端 `approachReason` 那句中文里**（「参考最优解用的是「哈希、辅助数组」…」），前端要拿只能正则抠中文——改一个字就失效。已在 `CodeGrader` 的 `reference` 里补了结构化的 `optimalTechs` 字段，前端不再解析中文。

换一道题不会串用上一题的成绩：`State` 里连 `slug` 一起存，进错题弹窗前先比对 `State.lastGradeSlug === slug`，不等就当没评分处理。

### 每条错题都有「看题」入口 —— 修的是数据链路，不是补个按钮

早先的记录里「字母异位词分组」有「看题」按钮、「两数之和」没有。看着像按钮忘加，真实原因在数据：

错题表里 `problem_slug` 是**选填**的（手记时很多人只写题名，比如「1. 两数之和」），于是那条记录的 `problem_slug` 是空串，前端 `m.problemSlug ? 画按钮 : ''` 就把按钮吞了。**只补按钮等于治头痛，下次再手记一条同样的坑还会炸。**

三处一起补：

1. **老数据自愈**（`ApiController#mistakes`）：返回列表前，`problem_slug` 为空的记录用题名去题库反查（`ProblemStore#resolveSlugByTitle`，中文名 / 英文名 / slug 三个字段都试，并剥掉 `1.` `[1]` `1、` 这类题号前缀），命中就补进返回值**并写回数据库** —— 只补一次，不是每次请求都白算。
2. **新数据入库即关联**（`ApiController#addMistake`）：`POST` 时 slug 为空就先按题名反查，别让同一条错题下次还要靠自愈。
3. **兜底不留死按钮**：万一题库里真没这道题，按钮也得在 —— 变成「去题库找」，跳过去自动把题名填进搜索框并直接搜。**点了没反应的按钮比没有按钮更糟。**

自动补上的那条会带 `slugGuessed: true`，前端能分辨「这是当初填的」还是「这是按题名猜的」。

> 为什么不干脆把 `problem_slug` 改成必填？因为错题本要能记**题库里还没有的题**（看到一道不会的题，还没拉进题库就想先记下来）。必填会把这个场景堵死。

### 错题本分页：一页 6 道

错题攒到几十条以后，一屏滚到底既慢又看不出有几条。现在一页 6 道，超过一页才出分页条。

四个决定：

| 决定 | 为什么 |
| --- | --- |
| 页码只存内存，不进 URL | 错题本没有自己的路由。塞进 hash 后，删除 / 标记掌握还得同步 hash，多一处能对不上的状态 |
| 页码会被夹回合法范围 | 在最后一页删掉最后一条，原页码就指到空气里了。夹住而不是报错 —— 删到空页是正常操作 |
| 翻页不重新请求接口 | `State.mistakes` 里已经是全量数据，为了翻页再打一次网络纯属浪费 |
| 只有一页时不画分页条 | 一条错题还显示「1 / 1」是噪音 |

页码超过 7 个时用 `…` 收中间（首页、末页、当前页前后各一个必留），否则 20 页的错题本能把分页条撑爆。

### 三个解法默认都是锁住的

打开题目页，三个 tab 全是 🔒，各自独立上锁、**互不联动**：点开「解法 2」不会顺带放出「解法 1」。这一点是刻意的——能分三次看答案，才有三次自己先想的机会。

- 点锁屏卡 → 只解锁这一块，tab 图标变 🔓，顶部计数 +1
- **再点一次已解锁的那个 tab → 这一块重新锁上**（不用跑去点顶部按钮）
- 「全部重新上锁」把这道题恢复到三个全锁
- 键盘也能用：Tab 聚焦到锁屏卡，回车 / 空格等于点一下
- 解锁状态存 `sessionStorage`（键 `lc.sol.unlocked`，按 slug 分题记）：同一标签页里再进来还是解锁的，**关掉标签页自动重置**——第二天重做时又是一道新题
- 锁着的时候，解法的 `title` / `idea` / 伪代码 / Java 代码**根本没有写进 DOM**（`renderSolTabs` 里 `locked ? lockCard(...) : solBody(...)`），不是靠 CSS 遮住，F12 也翻不出来

## 改前端不用重启（热更新）

前端文件已经从 jar 里搬到了项目根的 `static/`：

```
static/
  index.html
  app.js              主逻辑
  app.css             样式
  lock.js             解法上锁
  roast.js            评分锐评
  mistake-fill.js     错题自动填写
  snippet-kinds.json  模板可用性判定（由 CompileCheck.java 生成）
```

`application.yml` 里把静态目录指到了磁盘：

```yaml
spring:
  web:
    resources:
      static-locations: file:./static/,classpath:/static/
      cache:
        period: 0
```

`file:./static/` 排前面，所以**磁盘优先、jar 内 classpath 兜底**（万一 `static/` 被删了页面也不会白屏）。`cache.period: 0` 让浏览器每次回源，改完刷新就能看到。

改完直接 Ctrl+F5，**不用重新打包、不用重启 java**。已验证：往 `static/app.css` 追加一行注释，立刻 `fetch` 就能读到；改回来立刻读不到。

注意两点：
- `src/main/resources/static/` 里的副本是「打包进 jar 的备份」，**日常改的是 `static/` 那一份**。要重新打包发版时记得两边同步（`cp static/* src/main/resources/static/`），否则别人拿去部署看到的是旧版。
- 只有前端文件能这样热改。改 Java 代码、改 `content/` 里的题目 JSON 仍然要重新打包重启。

### 复制按钮：为什么在局域网里点不动

页面上有五个「复制」按钮（今日模板、三个解法、我的代码、模板库），它们现在都走同一个 `copyText()`。

**改之前是四个调用点各自裸调 `navigator.clipboard.writeText`，一点就弹红色的「复制失败，手动选中吧」。** 原因不在按钮：`navigator.clipboard` 只在**安全上下文**里存在 —— `https`、`localhost`、`127.0.0.1` 才算。从局域网 IP（比如手机或另一台电脑访问 `http://192.168.x.x:8099`）打开时，这个属性**干脆是 `undefined`**，读它的那一刻就抛 `TypeError`，被 `catch` 吞成一句「复制失败」。而服务监听的是 `0.0.0.0:8099`，本来就是给别的设备访问的 —— 这条路必须走得通。

`copyText()` 分两条路：

| 顺序 | 手段 | 什么时候用 |
| --- | --- | --- |
| 1 | `navigator.clipboard.writeText` | 安全上下文、有权限 |
| 2 | `execCommand('copy')` + 临时 textarea | 上面不可用或被拒 —— 老、丑，但非安全上下文里只有它能用 |

顺序不能反：先 clipboard（现代、无副作用），失败再兜底。反过来会在安全上下文里也去插临时 textarea，平白闪一下。

**兜底的 textarea 必须真的选中。** 不选中就调 `execCommand('copy')`，复制进去的是上一次的选择内容 —— 那比失败更糟，用户粘贴出来是别的代码，还以为自己复制对了。所以 `ta.select()` 之后还要 `setSelectionRange(0, s.length)`，`finally` 里无论成败都把节点摘掉。

**两条路都废时，提示要说清为什么**：「复制失败：浏览器不允许当前地址写入剪贴板。用 https 或 localhost 打开，或者手动选中复制」。原来那句「手动选中吧」把权限问题说成操作问题，只会让人反复点。

> **顺手抓到的两个真 bug（都是我自己上一版补丁写出来的）**：改这四处时把 `$$(...)`（返回数组）手滑写成了 `$(...)`（返回单个节点），后面接 `.forEach` 就是 `Cannot read properties of null`。三处：今日模板、`bindCopy`、模板库。**`node --check` 不报这个错** —— 语法本身是对的，只有真跑起来才炸，今日页直接白屏。现在 `test-copy.js` 第 5 节扫全文，专门守这一类。

`static/app.js` 里 `copyText()` 紧跟着 `toast()` 定义，四个调用点都在它下面。

### 看不到新版怎么办

浏览器会缓存旧的 `app.js`。判断你加载的是哪一版，看**侧栏最下面那行灰色小字**：

```

```

没有这行字，说明你加载的是旧版前端 —— 按 `Ctrl+F5` 强制刷新（或关掉标签页重新打开）。

另外 `app.js` 开头对 `lock.js` 做了兜底：万一 `lock.js` 因为缓存没加载成功，题目页也不会整页白屏，而是三个解法全部显示「刷新页面」的锁屏卡（宁可锁死，也不能崩）。

## 模板库为什么要有一个 `SnippetStore`

准备推到 GitHub 时发现一个真缺陷：**52 段模板原来只存在数据库里。**

当初是写 `seed-snippets.js` 一段段 POST 进去的，数据库里有，所以自己机器上一切正常。但只要换台机器、或者把 `data/` 删了重来，模板库就是空的 —— 而模板库是五项需求之一。

靠「记得先跑一遍 seed 脚本」来保证它存在，那不叫功能，叫运气。别人 clone 下来发现模板库空的，不会觉得是自己漏跑了一步，只会觉得这东西是半成品。

所以加了 `SnippetStore`（`src/main/java/com/lc/service/SnippetStore.java`），`@PostConstruct` 里检查 `snippet` 表：

```
表里有数据  → 什么都不做
表是空的    → 从 content/snippets.json 灌 52 段
```

三条设计决定：

| 决定 | 理由 |
| --- | --- |
| **只在表为空时灌** | 用户可能自己加过、删过模板。每次启动都补回来，等于一遍遍抹掉他的编辑 —— 一个会自动还原你删除操作的功能，比没有功能更烦人 |
| **数据放 `content/snippets.json`** | 和 `content/problems/` 一样的思路：内容归内容，代码归代码。加模板不用改 Java，也不用重新编译 |
| **灌失败不拦启动** | 模板库空着顶多少一个功能，服务起不来是整个项目不能用。这两件事的代价差太远，不能同归于尽 |

`snippets.json` 里**没有 `id` 字段** —— 各环境自增序列不同，带上别人的 id 只会撞车，让数据库自己发号就行。`sortOrder` 要保留，否则 52 段模板的展示顺序会乱。

### 日志乱码：`-Dfile.encoding` 管不到控制台

第一次验证时启动日志打出来是这个：

```

```

启动命令明明加了 `-Dfile.encoding=UTF-8`。原因是**那个参数管文件读写，管不到 JVM 的 stdout** —— Windows 上控制台默认还是 GBK，重定向到 `run.log` 之后按 UTF-8 读就是一堆问号。

## 打卡按钮为什么曾经在昨天/明天失效

**现象**：今天计划里的 ✓ 点了有反应，翻到昨天或之后的日子，✓ 看上去能点，点下去什么都没发生 —— 没有网络请求、没有报错、界面不动。

**根因不在按钮，在一道多余的闸**。`viewToday()` 里曾经有：

```js
const canCheck = t.isToday !== false;
$$('[data-check]', main).forEach(btn => {
  if (!canCheck) {
    btn.disabled = true;                     // 只是变灰
    btn.title = '这是历史/未来的安排，切回今天才能打卡';
    btn.addEventListener('click', e => {      // 点了只弹 toast
      e.stopPropagation();
      toast('这是第 ' + t.dayNo + ' 天的安排，切回今天才能打卡');
    });
    return;                                   // ← 真正的绑定时这里就 return 了
  }
  ... 真正的打卡逻辑
});
```

当初的理由写得很像回事：「那个勾写进的是真实今天的进度，在历史页点它等于偷偷改今天」。**这个前提是错的**：

| 表 | 主键 | 有没有「按日」这个维度 |
| --- | --- | --- |
| `progress` | `slug` | 没有。`done_date` 只记**第一次**完成的日期，`status` 只有 `done` / `todo` |
| `plan_day` | 计划的第几天 | 有，但它存的是**计划**（那天该做哪几题），不是**完成情况** |

所以「给第 3 天的题打卡」语义上就是「把这道题标记成做过」，和它是哪一天的安排毫无关系。后端 `POST /api/progress/{slug}` 从头到尾不认识日期参数，它本来就是对的 —— **是我在前端自己加了一道闸把功能关掉了**。

**三道连带问题**（只改第一处不够）：

1. **`refreshToday(null)` 会覆盖 `State.today`**。原来打卡后无条件刷新「真实今天」，在历史页点勾会让侧栏的连续打卡、累计完成跳成今天的数字。改成 `refreshToday(t.isToday === false ? t.dayNo : null)` —— 看哪天刷哪天。
2. **进度条读的是 `State.today`**。历史页打卡后，进度条要显示「那一天」的完成度。改成读 `fresh || t`（当前渲染的那份）。
3. **提示条文案在撒谎**。原来写「这里的勾选记账本上的真实今天，不会改历史」——现在改成「打卡记的是「这道题做没做过」，不分哪天，所以在任意一天都能勾」。

**测试也跟着错了**：`test-day-nav.js` 里有一条 `ok('翻到别的日子时打卡按钮停用', /const canCheck = t\.isToday !== false/.test(app))` —— 它把 bug 当成规格钉住了。**这类「测试通过但产品是坏的」比没有测试更糟**：下次有人想修，测试会先拦住他。改成反向断言（不能再出现这道闸），并新增三个真实验证脚本。

**教训**：注释里写清了理由，不代表理由成立。这次的理由读起来很自洽，但它建立在一个没验证过的前提上（「progress 是按日记账的」）。**改判分/门控类的规则之前，先去库里看一眼那张表的主键是什么。**

## 临时目录不可写：一个把我自己坑进去的故障

### 症状

用户提交的代码在力扣上通过了，这里却报编译失败，界面上只有一行：

```
编译过程出错：C:\Users\...\Temp\...\lcgrade4584956653082003117
```

**一个路径，没有类型，没有原因。** 用户完全没法判断到底是自己代码的问题还是环境的问题。

### 根因

`Files.createTempDirectory("lcgrade")` 只看 `java.io.tmpdir`。而那个目录**虽然存在，ACL 却不允许建子目录** —— 这是最容易误判的一点：`ls` 看得到目录，`mkdir` 却 `Permission denied`。

更糟的是 `AccessDeniedException.getMessage()` **只返回路径本身**，不带异常类型也不带原因，所以界面上就成了一句纯路径。**报错不解释等于没报错。**

### 两层都要修，第二层更致命

| 层次 | 后果 | 修法 |
| --- | --- | --- |
| `CodeGrader` 建不了编译产物目录 | 评分永远失败 | `newOutDir()` 按 `java.io.tmpdir` → `data/grade-tmp` 顺序试探，谁先能建出来就用谁 |
| Spring Boot 建不了 Tomcat baseDir | **整个服务起不来** | `App.main()` 里 `SpringApplication.run` 之前先 `ensureTempDir()` |

第二层是在修第一层时发现的：服务直接 `exit 1`，栈顶是 `WebServerException: Unable to create tempDir`。**这说明「某个功能坏了」和「整个项目打不开」之间只差一个 tmpdir。**

### 三个实现要点

1. **「目录存在」和「能建子目录」是两件事。** `canCreateIn()` 是真的建一个探针目录再删掉，不是 `Files.exists()`。
2. **改 `java.io.tmpdir` 不够，还要改 `server.tomcat.basedir`。** Tomcat 走的是自己的配置项。
3. **降级候选里要有一个确定可写的位置。** 第一位是项目目录下的 `.jtmp/`（已被 `.gitignore` 忽略），最后才退到 `~/.lc-coach/tmp`。

启动成功时日志第一行会明说换了哪个目录：

```
临时目录不可用（C:\Users\...\Temp\dsh-uohuIR\），已改用 E:\moren\lc-coach\.jtmp
```

找不到任何可写位置时不硬崩，而是打一行警告让服务继续起 —— **编译评分用不了是少一个功能，服务打不开是整个项目不能用，这两个后果差太远。**

## 数据备份与恢复

### 为什么会做这个

曾经因为一次清理操作把 `data/lccoach.mv.db` 删了，打卡记录、错题本、力扣绑定全部归零，而且**没有任何备份可以恢复**。

一个存着个人学习数据的工具没有备份，是设计缺陷，不是运维疏忽。所以现在 `BackupService` 会自动做这件事。

### 什么时候备份

| 时机 | 说明 |
| --- | --- |
| 启动后立刻 | 库里最干净、最能反映「启动那一刻」的状态 |
| 每 6 小时 | 服务长期开着时，中途的数据同样需要保护 |

备份文件落在 `data/backup/`，文件名形如 `lccoach-20261103-092844-startup.zip`，**只保留最近 7 份**，多了删最旧的。

### 怎么备份的

用 H2 自己的 `BACKUP TO`，**不是直接拷 `.mv.db` 文件**。原因：直接拷的时候数据库可能正在写，拷出来的是撕裂的；`BACKUP TO` 是一致性快照。

备份失败只写日志，不抛异常 —— 少一层保险可以，但让业务因此挂掉是本末倒置。

### 怎么恢复

```bash
# 1. 停服务（否则文件被占用）
powershell -NoProfile -Command "Get-Process java,javaw -ErrorAction SilentlyContinue | Stop-Process -Force"

# 2. 挪走坏掉的库，别覆盖它 —— 万一还能救
mv data/lccoach.mv.db data/lccoach.mv.db.broken

# 3. 用 H2 自带的 Restore 还原（<h2.jar> 换成你本机路径）
java -cp "<h2.jar>" org.h2.tools.Restore \
     -file data/backup/lccoach-<时间戳>-startup.zip -dir data

# 4. 启动，确认数据回来了
java -jar target/lc-coach-1.0.0.jar
```

**两个不能用的方式**（都实测过报错）：

| 错误做法 | 为什么不行 |
| --- | --- |
| `RUNSCRIPT FROM 'xxx.zip'` | 那是给纯 SQL 脚本用的；`BACKUP TO` 产出的是装 `.mv.db` 的二进制 zip |
| 手工 `unzip` 再拷文件 | 名字能对上，但绕过了 H2 的校验；`org.h2.tools.Restore` 才是设计上的入口 |

`org.h2.tools.Restore` 还原出来的库文件是完整的 131072 字节，能直接当数据库查询 —— 这一点已实测确认。

## 模板库的「可直接用 / 片段」是怎么判出来的

模板库里的代码有两种，用同一把尺子量会得出错误结论：

| 标记 | 含义 | 怎么判的 |
| --- | --- | --- |
| 可直接用 | 能整段贴进力扣跑 | `CompileCheck.java` 用 JDK 的 `JavaCompiler` 真编译通过 |
| 片段 | 教学示意，示范写法但不是完整程序 | 编译不过，但属于「缺外部变量/类」「顶层散语句」「含中文占位符」 |
| 有问题 | 真写错了 | 括号/注释没闭合，或语法级错误 |

**判定只有一份实现**（`content-src/CompileCheck.java`），它把结果写成 `static/snippet-kinds.json`，前端只读这个文件、不复刻正则——两套规则并存迟早漂移，界面标「可用」而实际编译不过，比不标更害人。

为什么会有「片段」这一类：`x & (-x)`、`(x & 1) == 1` 是表达式速查；`void dfs(int[][] grid, int i, int j)` 依赖外部的 `grid` 和方向数组。把它们当完整程序编译必然失败，但这不是错误——它们的用途是「照着写」，不是「直接粘」。

改完模板后重新跑一遍，退出码 0 表示没有真错误：

```bash
"E:/Program Files/Java/jdk-21/bin/java.exe" -Dfile.encoding=UTF-8 \
  -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8 content-src/CompileCheck.java
```

### 为什么不 spawn javac

沙箱里 Node 子进程 exec `javac.exe` 直接 `EPERM`（文件存在、`javac -version` 在 shell 里也能跑，但子进程不行）。只能走 JVM 内部的 `ToolProvider.getSystemJavaCompiler()`——`CodeGrader` 给用户代码打分用的也是它。

## 内容生产管线

题面和代码是分开的，加题不用改 Java：

```
content-src/
  gen/bNN.js         手写解法（每题 3 个，tier 必须 brute/better/optimal）
  gen/lib.js         L() 拼代码行 + write() 校验 tier 顺序后落盘
  solutions/*.json   → content/solutions/<slug>.json
  merge.js           合并进 content/problems/<slug>.json
  verify.js          校验：3 解法、tier 顺序、idea 长度、伪代码行数、方法签名对比力扣模板
  compile.sh         导出全部解法逐个 javac（含 support 类）
  support/           TreeNode / ListNode / Node（本地编译用，提交力扣不需要）
```

加一道新题：

```bash
# 1. 写 content-src/gen/bNN.js，用 write('slug', [s1, s2, s3])
node content-src/gen/bNN.js
# 2. 合并进题目 JSON
node content-src/merge.js
# 3. 校验（120 题全过才允许提交）
node content-src/verify.js
# 4. 编译全部解法
bash content-src/compile.sh
```

当前状态：`verify.js` 输出 **完全合格 120 / 有问题 0**，`compile.sh` 输出 **编译通过 360 / 失败 0**。

### 写批次文件的两条硬规则

1. **Java 代码行用双引号包裹**，这样行内的单引号字符常量（`'0'`、`'Q'`）不会截断 JS 字符串：
   ```js
   "        board[row][col] = 'Q';",
   ```
2. **`idea` / `title` / `pseudocode` 里不写裸引号**，用「」或全角符号代替。写批次文件时曾在 `"())."` 这种字符串上被截断过三次。

写完先 `node --check content-src/gen/bNN.js` 再跑。

## 后台任务

- **每日提醒**由 `ReminderService` 的 `@Scheduled(fixedDelay = 60_000)` 驱动，到点往 `notify` 表写一条站内信，前端进页面轮询 `/api/notify/unread` 显示红点。已实测：改时间到过去时刻 → 60 秒内自动生成；`/api/notify/push` 立即生成；重复调 push 同一天不重复发。
- 要注意的边界：**服务没在跑的时候不会有任何提醒**。这不是遗漏，是本地单机应用的物理限制——定时任务活在 JVM 里。想让提醒在服务不跑时也到达，只能接外部推送（钉钉/飞书/Server酱 webhook），`ReminderService.pushDaily()` 里留了插入点。


## 为什么不用 ORM / 前端框架

这个项目的价值在内容和练习闭环，不在框架演示。JDBC + H2 让加一张表就是一段 `CREATE TABLE`，题目内容用 JSON 存放，加题不碰 Java。前端用原生 JS 是为了改样式时不用等构建。

## 让服务一直活着（重要）

命令行后台启动的 java 进程会随父 shell 退出被杀掉（`exit code 127`），`Start-Process` / `cmd start` / VBS 在本沙箱里同样会被回收。所以：

- **日常使用**：双击 `启动-免编译.cmd`，保持那个黑窗口开着。关窗口即停服务。
- **不想每次点**：双击 `安装开机自启.cmd`（需管理员），注册成「登录时自动启动」的计划任务，之后开机就在跑。卸载用 `卸载开机自启.cmd`。

已实测：前台启动后 `/api/today` 正常返回、`解析失败 0`，jar 本身没问题，只是进程保活需要靠外壳程序。
