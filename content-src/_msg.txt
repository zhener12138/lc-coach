评分器接入真跑判题：从「猜」换成「真跑」

用户问「这个代码评分好多都是猜的，他不能真的测试，然后根据测试去打分吗」。
确实只有编译一项是真的，其余五项全是正则扫代码结构猜出来的。
这次把「正确性」变成实测维度。

三道坎：

1. 用例从哪来 —— 项目里一条测试用例都没有，只有展示用的题面 HTML。
   用力扣 GraphQL 的 exampleTestcases + metaData 拿官方示例输入和方法签名，
   但期望输出它不给，改用参考最优解跑一遍当标准答案。为此加了自检：
   参考解跑不通全部用例就把这道题标记为「参考解有问题」并停止判题，
   而不是拿一个错答案去判用户。用例落在 content/tests/，116 个文件随仓库分发。

2. 用户代码在哪跑 —— 这台机器禁止 Java 创建任何子进程：
   ProcessBuilder 报 CreatePipe error=5；改成全文件重定向后进程能起但
   EXIT -1073741502（STATUS_DLL_INIT_FAILED）；连 cmd /c echo hello 都一样。
   所以退到同进程执行：JavaCompiler 编译后 URLClassLoader 加载 + 反射调用。
   代价是隔离性差，为此加了两道保护：每个用例 3 秒超时（死循环掐掉而不是
   挂住服务）、截获 System.out（避免刷爆日志）。

3. 判不了怎么办 —— 116 题里 110 题能真判。剩下 6 题是类型系统表达不了：
   设计类没有单一 Solution 函数、链表环题比的是节点引用、LCA 传的是树内节点、
   clone-graph 缺 Node 类定义。这 6 题把「正确性」维度整个剔除并按剩余六项
   重新归一，不给 0 分 —— 判不了是这边能力不足，不该记在用户头上。

权重按可信度重排：compile 0.12 / correctness 0.30 / approach 0.14 /
complexity 0.16 / space 0.10 / edge 0.10 / style 0.08。
两项实测加起来 0.42，正确性一项顶过任何两项推断。
新增两条一票否决：有用例没过封顶 7.9；通过率不到一半再压到 6.9。
通过率映射刻意做成非线性 1 + 9×rate²，过一半只有 5.0 分。

效果（真实数据）：
- 两数之和正确解法：10.0 → 10.0（3/3）
- 两数之和写死 return new int[]{0,1}：9.5 虚高 → 6.9（2/3，正确性 5.0）
- LRU 缓存参考解：10.0，正确性维度剔除

顺带修的：
- store.dir() 是相对路径只有两级，getParent().getParent() 返回 null，
  导致判题静默不执行 —— 改成先 toAbsolutePath()。这个 bug 只有靠
  「探针单独跑通、接进评分器就不跑」才暴露出来。
- test-judge.js 第 6 节原来读一份探针输出文件，文件被清理后悄悄走了
  「跳过」分支 —— 不报红但也没验证。改成直接打真实接口，服务没起就
  明确失败。一个永远跳过的测试等于没有测试。
- test-grade.js 三处过期断言（「不判答案对不对」、写死六个维度）改成
  「6 或 7 项」—— 能判题=7、判不了=6，写死数字会给未来的自己埋雷。
